A retry budget beats unlimited retries for tool-calling agents

I gave a tool-calling agent a fixed per-task budget of retries instead of letting it retry each failing call up to five times. Task success rose from 71% to 84% on 400 held-out tasks while tool calls per task fell by a third.

1Motivation

Retry logic is usually written once, per tool, and forgotten. Each tool wrapper retries up to five times with backoff. That is reasonable for a flaky network and wasteful for a call that fails because the arguments are wrong: the agent sees the same error five times and still has to change its plan afterwards.

This report asks one question. If the retries are pooled into a single budget for the whole task, does the agent spend them better?1

2Method

The agent gets a budget B of failed calls per task. Every failed tool call, whatever the tool, spends one unit. When the budget reaches zero the agent must answer with what it has, or stop and explain what is missing.

2.1 What counts as a failure

  • A tool returns a typed error (validation, not found, permission).
  • A tool times out after 20 s.
  • The model emits a call that does not parse.
Note

Network errors with a Retry-After header are retried by the transport and never reach the budget.

5Analysis

5.1 Where the retries went

In the baseline, 62% of retries repeated a call with identical arguments. Under the budget that share fell to 9%: after one failure the agent usually switched tools or asked a narrower question.

5.2 When it does not help

With untyped errors (a raw stack trace instead of NotFound), success under B = 6 was 72.4%, within noise of the baseline. The budget only helps if the agent can tell why a call failed.

6Limitations

Caveat

One model, one task set. The best budget is likely task-dependent; treat B = 6 as a starting point, not a constant.

  • Tasks are English-only and short (median 9 steps).
  • Cost assumes list prices in November 2026.

7Reproducing

Everything in Table 2 and Figure 2 runs from one script. A full sweep takes about 3 hours on the hardware in Table 1.

# clone at the commit this report was written against
git clone

pip install -r requirements.txt

# run the sweep and write results/table2.csv
python run_sweep.py --budgets 3 6 12 --seeds 3
budget.py
class RetryBudget:
    def __init__(self, total: int = 6):
        self.left = total

    def spend(self) -> bool:
        # returns False when the agent must stop retrying
        self.left -= 1
        return self.left >= 0
